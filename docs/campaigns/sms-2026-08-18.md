## 6. Landing / CTA review (`/l/one`)

`/l/one` is serving the **generic default landing**, which fights the campaign:

| # | Problem | Effect |
|---|---|---|
| 1 🔴 | **Audience mismatch** — sub-copy is a *B2B wholesale* pitch ("تأمین‌کننده عمده… برای فروشگاه‌ها"). Wrong message for consumer clicks. | Instant bounce |
| 2 🔴 | **Generic CTA** — "مشاهده محصولات" has no offer/urgency and doesn't echo the SMS promise. | Weak pull |
| 3 🟠 | **Full-viewport hero** (`min-h-100svh`) — on mobile the whole first screen is video + one button; products/prices are below the fold. | They never see a product |
| 4 🟠 | **No price/hook above the fold** — gold buyers anchor on نرخ روز + pieces; none visible until scroll. | Nothing to grab them |
| — | 1.2 MB autoplay hero video (deferred, so LCP is OK, but heavy on mobile data). | Minor |

*(Scroll-depth events aren't archived in Matomo, so #3 is inferred from the 90
exits + 101 reloads at the landing — consistent, not directly measured.)*

---

## 7. Recommendations (highest leverage first)

1. **Make `/l/one` match the SMS** — no code; landings are admin-editable.
   Consumer headline, the actual offer, and a CTA that names it
   ("مشاهده کالکشن جدید" / "خرید با نرخ امروز").
2. **Shorten the hero** to ~75svh (or surface the نرخ روز strip + first product row)
   so something shoppable peeks above the fold. Small change in `HeroSection`.
3. **Add a `همه محصولات` button in the hero** so `/shop` is one tap from the top,
   not buried after the product groups.
4. **Investigate checkout** — 2 carts formed, **0 checked out**. Walk the cart →
   login/OTP → order flow on mobile and look for friction (forced login, OTP
   failures, price/weight confusion). With so few carts one broken step = 0 orders.
5. Optional: drop the autoplay video on campaign landings — poster-only paints faster.

**Impact math:** moving landing→shop pass-through from **12% → 30%** roughly
**triples** every upstream step — but only matters if checkout actually converts,
so fix #4 in parallel.

## Appendix — how these numbers were pulled

- **Instance:** self-hosted Matomo 5.9.0, `didargold-fnebllvlkk.liara.run`, site id 1, tz Asia/Tehran.
- **Landing clicks:** segment `entryPageUrl=@/l/one`, `VisitsSummary.get`, period=day.
- **Timing:** `VisitTime.getVisitInformationPerServerTime` (site-tz hours).
- **Funnel:** `Transitions.getTransitionsForPageUrl` for `/l/one` and `/shop`;
  cart/orders via `Goals.get` (`ecommerceAbandonedCart`, `ecommerceOrder`).
- **Note:** the `visitServerHour` segment field is **UTC** (site hours are UTC+3:30),
  so "16:00 Tehran" ≈ `visitServerHour>=12`.
