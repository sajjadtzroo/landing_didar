# گزارش توسعه دیدار گلد + برنامه کمپین تبلیغاتی ماتومو

تاریخ گزارش: ۲۱ شهریور ۱۴۰۵ (۱۲ سپتامبر ۲۰۲۶)
دامنه: [didargold.ir](https://didargold.ir) — روی سرور اختصاصی (VPS)

## بخش اول — کارهای توسعه انجام‌شده

### ۱. کنترل نمایش مشخصات محصول (قیمت‌گذاری برای اعضا)

- سوییچ در پنل ادمین (`/admin/settings`): نمایش اجرت فقط برای کاربران واردشده یا برای همه.
- وزن و عیار همیشه عمومی است؛ فقط **اجرت** پشت ورود قرار می‌گیرد و مهمان‌ها پیام «برای مشاهده مشخصات وارد شوید» می‌بینند.
- جدول `site_settings` در دیتابیس + API عمومی `/settings` بدون کش (تغییر ادمین فوراً اعمال می‌شود).
- رفع چند باگ مسیر: خطای ۵۰۰ در PATCH (تداخل علامت `$` در هش و کست JSONB)، جهت اسلایدر سوییچ، و تایمینگ SSR در Nuxt.

### ۲. ناوبری هوشمند (لندینگ ↔ فروشگاه)

- کاربری که از لندینگ (`/l/one` و…) وارد می‌شود، در صفحه محصول نوار «بازگشت به لندینگ» می‌بیند؛ کاربر مستقیم فروشگاه، breadcrumb عادی.
- لینک «خانه» در نوبار فقط برای کسی که از لندینگ آمده نمایش داده می‌شود و به همان لندینگ برمی‌گردد.

### ۳. سیستم تصاویر محصول (گالری + MinIO + WebP)

- دکمه آپلود تصویر در فرم ساخت/ویرایش محصول (ذخیره در MinIO).
- **آپلود چندتایی**: انتخاب چند عکس هم‌زمان؛ در حالت ساخت محصول، عکس‌ها بعد از ذخیره به‌صورت خودکار آپلود می‌شوند.
- تبدیل خودکار هر عکس به **WebP** در سرور + ساخت نسخه ۶۴۰ پیکسلی (`-sm`) برای کارت‌ها.
- ذخیره در پوشه `products/{SKU}/` — همان ساختار همگام‌سازی عکاس.
- پردازش موازی (asyncio.gather): آپلود N عکس تقریباً هم‌زمان انجام می‌شود.
- دکمه «ویرایش» روی صفحه محصول برای ادمین واردشده (میان‌بر به پنل).
- تست خودکار برای آپلود چندتایی و رد کردن فایل خراب.

### ۴. پیامک PayamSMS

- جایگزینی Kavenegar با وب‌سرویس REST نسخه ۲.۱ پیام‌اس‌ام‌اس برای OTP و اعلان سفارش (کامیت‌های قبلی همین دوره).

### ۵. استقرار روی سرور اختصاصی (VPS) — از صفر

| مرحله | جزئیات |
|---|---|
| امن‌سازی سرور | آپدیت کامل Ubuntu 26.04، کاربر sudo جدا، کلید SSH، فایروال UFW (فقط ۲۲/۸۰/۴۴۳)، fail2ban، آپدیت امنیتی خودکار، تایم‌زون تهران، سواپ ۲GB |
| زیرساخت | Docker + Compose (مخزن رسمی)، میرور رجیستری آروان، محدودیت لاگ، Nginx روی هاست |
| استک برنامه | ۴ کانتینر: Postgres 16 و Redis 7 (بدون پورت عمومی)، بک‌اند FastAPI و فرانت Nuxt فقط روی loopback |
| Nginx | پروکسی `/api` و `/media` به بک‌اند، `/` به فرانت، وب‌سوکت چت، gzip، سقف آپلود ۲۰MB |
| عملیات | بکاپ روزانه pg_dump (نگهداری ۷ روز)، اسکریپت `deploy.sh` با health-check و راهنمای rollback |
| رفع مشکلات شبکه ایران | build فرانت به‌دلیل قطع npmjs محلی انجام و ایمیج از طریق SSH ارسال شد؛ ایمیج‌های گرافانا/پرومتئوس هم همین‌طور |
| باگ مهاجرت دیتابیس | خطای enum در دیتابیس تازه (`transaction_per_migration`) ریشه‌یابی و رفع شد — کل زنجیره ۳۲ مایگریشن روی دیتابیس خالی تست شد |

### ۶. انتقال کامل داده از لیارا

- ۵۸ محصول با تمام مشخصات + گالری تصاویر (نگاشت ID از طریق SKU).
- حذف ۱۰ محصول نمونه (seed).
- ۱۰ سؤال متداول، ۳ لندینگ (one/two/three) با محتوای کامل، ۴ کالکشن (عید، عروس، دیدارنیو، سیلون‌گلد).
- تصاویر از باکت مشترک MinIO سرو می‌شوند — بدون جابه‌جایی فایل.

### ۷. اتصال دامنه و HTTPS

- رکوردهای DNS از طریق API لیارا به IP سرور تغییر کرد؛ دامنه از اپ لیارا جدا شد.
- ریشه‌یابی گیر انتشار DNS لیارا (رکوردهای ساخته‌شده قبل از جداسازی publish نمی‌شدند).
- گواهی Let's Encrypt برای `didargold.ir` و `www` + ریدایرکت HTTP→HTTPS + تمدید خودکار (تست شد).
- کوکی‌های امن و originهای production فعال شد.

### ۸. مانیتورینگ (Grafana + Loki)

- استک کامل: Loki (لاگ)، Alloy (جمع‌آوری)، Prometheus (متریک)، Grafana (داشبورد + هشدار)، cAdvisor و node-exporter.
- گرافانا پشت Nginx در didargold.ir/grafana/ (بدون پورت باز اضافه).
- ۸ قانون هشدار آماده (نرخ 5xx، تأخیر p95، قطع بک‌اند، حمله brute-force، کوئری کند، دیسک، رم، سکوت لاگ) — برای فعال‌سازی تلگرام فقط توکن ربات لازم است.
- رفع باگ تصاویر بهینه‌شده (IPX) که به هاست قدیمی لیارا اشاره می‌کرد.

## بخش دوم — برنامه کمپین تبلیغاتی با ماتومو

زیرساخت ماتومو از قبل کامل است (اهداف، دایمنشن‌ها، ecommerce — طبق `docs/analytics-matomo.md`). برای کمپین فقط باید **لینک‌های برچسب‌دار** بسازیم و گزارش بگیریم.

### ساختار لینک کمپین (پارامترهای mtm)

الگوی استاندارد برای هر تبلیغ:

```
https://didargold.ir/l/one?mtm_campaign=CAMPAIGN&mtm_source=SOURCE&mtm_medium=MEDIUM&mtm_content=CREATIVE
```

| پارامتر | معنی | مثال |
|---|---|---|
| `mtm_campaign` | نام کمپین | `mehr-sale` |
| `mtm_source` | منبع ترافیک | `instagram`, `telegram`, `google` |
| `mtm_medium` | نوع کانال | `story`, `post`, `influencer`, `cpc` |
| `mtm_content` | نسخه خلاقانه (برای A/B) | `video-a`, `photo-b` |

### لینک‌های پیشنهادی کمپین اول (مهر ۱۴۰۵)

```
اینستاگرام استوری  → https://didargold.ir/l/one?mtm_campaign=mehr1405&mtm_source=instagram&mtm_medium=story&mtm_content=v1
اینستاگرام پست    → https://didargold.ir/l/one?mtm_campaign=mehr1405&mtm_source=instagram&mtm_medium=post&mtm_content=v1
تلگرام کانال      → https://didargold.ir/l/two?mtm_campaign=mehr1405&mtm_source=telegram&mtm_medium=channel&mtm_content=v1
اینفلوئنسر        → https://didargold.ir/l/three?mtm_campaign=mehr1405&mtm_source=influencer&mtm_medium=story&mtm_content=NAME
```

نکته: هر اینفلوئنسر `mtm_content` مخصوص خودش بگیرد تا عملکردش جدا دیده شود.

### چه چیزهایی به‌صورت خودکار اندازه‌گیری می‌شود

- **بازدید کمپین**: Acquisition ← Campaigns در ماتومو.
- **تبدیل به سفارش**: Goal 1 «ثبت سفارش» با مبلغ واقعی (ریال) — به تفکیک کمپین.
- **تماس تلفنی**: Goal 2 / **شروع چت**: Goal 3.
- **استان مشتری** (dimension 1) و **منبع ورود** (dimension 2).
- مسیر حرکت کاربر: Users Flow (کدام لندینگ → محصول → سفارش).

### گزارش هفتگی پیشنهادی (۱۵ دقیقه در هفته)

1. Acquisition → Campaigns: کدام source/medium بیشترین بازدید و بیشترین **سفارش** را آورده.
2. نرخ تبدیل هر کمپین = سفارش ÷ بازدید؛ کمپین زیر ۰٫۵٪ را متوقف یا خلاقیتش را عوض کنید.
3. سگمنت «ورود از اینستاگرام» ← مقایسه با کل سایت.
4. هزینه هر سفارش = بودجه کمپین ÷ تعداد Goal 1 → معیار اصلی تصمیم.
